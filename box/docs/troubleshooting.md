### 14. Troubleshooting & Fallback Diagnostics

| Symptom | Root Cause | Remediation |
|---|---|---|
| `bwrap: setting up uid map: Permission denied` | Muse Code attempted inner bubblewrap; blocked by outer gVisor seccomp/`runsc` (not solely dropped caps) | Ensure the bypass is passed (automatic via `BOX_M_INNER_FLAG`, default `--disable-sandbox`) |
| `Project symlink points at ...` | Symlink inside the project resolves to a system dir, `$HOME`, or credential path | Remove or relocate the symlink outside the project tree |
| `Empty value for credential variable` | `KEY=` with no value in `providers.env` (empty values are rejected: they would arrive in-container as an empty env var and fail opaquely) | Fill in the value or delete the line |
| `must not include GID 0` | `*_EXTRA_GIDS` contains the root group | Drop `0` from the list |
| `Docker Engine >= 25.0 is required` | Old Engine lacks `bind-recursive` support | Upgrade the Engine; do not drop the mount flag |
| `unknown or invalid runtime name: runsc` (now: `Container runtime 'runsc' (gVisor) is not registered with Docker`) | gVisor `runsc` not installed or not registered in the Engine (`docker info` Runtimes lacks `runsc`); host-level, not per-repo — affects every project directory equally | Install gVisor per `operations.md` §5 (`runsc install` + `systemctl restart docker`, then `docker info --format '{{json .Runtimes}}'` must contain `"runsc"`), or explicitly use `--docker-fallback` (`box-m --docker-fallback` / `box-o --docker-fallback`) for hardened `runc` |
| `unexpected .../config.json replaced` | Pre-existing docker-cli config (proxies/credStore) was reset | Informational WARNING; original backed up to `config.json.bak` (mode 600, overwritten) |

| `Image UID/GID differs` | Container built with different IDs | Rebuild via `make build` (or `setup.sh`); never hand-run `docker build` (see `operations.md` §6) |
| `Project contains a socket/device/FIFO` | Host IPC endpoints in repo dir | Remove/relocate sockets, pipes, device nodes outside the project tree |
| `Image label reports ... but ... pins ...` | Built image tag vs pin-file mismatch | Synchronize `version-*.env` and rebuild (see `upgrades.md` §12) |
| `Missing credentials file` | No shared `providers.env` | Create mode-600 (400 accepted) `~/.config/box/providers.env` (`operations.md` §8); the file may stay empty — native `/connect` opencode users need no manual keys, and empty `KEY=` lines are rejected so only append non-empty values; `--dry-run` skips this check |

| `failed to write settings ... | `Unexpected server error` (opencode, Bun chunk) | Same class: `~/.config/opencode` parent on read-only rootfs; server could not write sibling state next to `opencode.json` | Fixed: launcher mounts writable `tmpfs` at `/home/box/.config/opencode` before the readonly `opencode.json` bind (`opencode debug config` must exit 0) |
| `Unsupported credential variable` | Unknown key in `providers.env` | Keep only the tool allowlist (`architecture.md` §7) |
| gVisor syscall failure (`ENOSYS`) | Toolchain needs unsupported syscall | Use the hardened runc fallback (`--docker-fallback`, e.g. `box-m --docker-fallback` / `box-o --docker-fallback`) |
| `login failed: device flow transport error: error sending request` (muse, at `Requesting a device login code…`) / `Could not resolve host` + `000` in-container (both `auth.meta.com` and `api.meta.ai`) while host `curl` succeeds | Docker embedded DNS (`127.0.0.11`) unreachable from inside the `runsc` sandbox on user-defined bridge networks — endpoint-side and upstream-independent (same image + network + in-container `resolv.conf` resolves under `runc` yet fails under `runsc`; `--dns` leaves the `127.0.0.11` endpoint unchanged on custom bridges and fails identically). Upstream mechanism: gVisor netstack owns sandbox loopback and does not apply the host netfilter remap for `127.0.0.11:53`. Host resolver, VPN residue, and firewall are exonerated as the differentiator. Past `auth.json` loss on ephemeral `tmpfs` is fixed separately (global persistent bind). | Standing behavior is AUTO: every tool run probes container DNS under `runsc` first and auto-selects hardened `runc` only when the probe fails (single `NOTICE` + the standard fallback `WARNING`, never silent; fail-closed under `BOX_M_ALLOW_FALLBACK=0` / `BOX_O_ALLOW_FALLBACK=0`). Probe exits 1/2 print the DNS `NOTICE`; any other nonzero probe exit (runsc startup failure or timeout, e.g. exit 125) prints a distinct `runsc failed to start or complete probe containers (exit N)` `NOTICE` instead, with the same heal and fail-closed behavior. `box-m login` / `box-m-login` share one global login in `~/.config/box-m/muse-config/auth.json`; `box-o` probes registry egress the same way. `--shell` never probes (explicit `--docker-fallback` there). Decision procedure (skip VPN/firewall/upstream re-diagnosis): same `getent` under `--runtime=runsc` vs `--runtime=runc` on the same image + network — `rc=2` vs `rc=0` with identical `resolv.conf` (`nameserver 127.0.0.11`) confirms this class. Upstream refs: `https://gvisor.dev/docs/user_guide/networking/`, `https://github.com/google/gvisor/issues/7469`. `verify-muse.sh` §3 (both endpoints) and `verify-opencode.sh` §3 catch regressions. |
| `(muse-spark-1.3 not in catalog — using assumed limits)` (muse, at startup) | Same class as the row above: the model-catalog fetch failed (typically the `runsc` DNS outage) while the catalog cache was empty, so the binary knows zero models — it ships no baked-in model IDs — and falls back to assumed context/output limits. The cache lives at `/persist/data/muse/muse/model-catalog/` inside the per-project volume, so every new project refetches on first run. Not a wrong seed: `muse-spark-1.3` + `reasoning_effort max` are both in the live provider catalog for device-login entitlements (verified 2026-09-07: catalog `source: provider_catalog`, `muse-spark-1.3` `is_current`, limits 1007997/128000, `max` in its effort variants). | Relaunch the run (AUTO heals to hardened runc with `NOTICE` + `WARNING`); for `--shell` use `--docker-fallback` explicitly. Do not "fix" by switching models — re-run and confirm the warning is gone. If it persists with working DNS, the entitlement's catalog genuinely lacks the ID: pick the replacement from in-container `/models` (device-login default is `muse-spark-1.3-contributor`, which trains on traffic — see `upgrades.md` §12 model pins for the seed-sync procedure). |

#### Fallback Runners
If a toolchain fails under gVisor's userspace kernel, run `box-m --docker-fallback` or `box-o --docker-fallback`. These execute under hardened `runc`, maintaining capability stripping (`--cap-drop=ALL`), `no-new-privileges`, non-root UID/GID mapping, isolated networking, and path protection while removing the syscall translation layer. The fallback also engages automatically, and only, when the pre-run container-DNS probe fails under `runsc` (see `operations.md` §9): one `NOTICE` plus the standard `WARNING` on every auto-select (never silent), fail-closed under `*_ALLOW_FALLBACK=0`. Probe exits 1/2 print the DNS `NOTICE`; any other nonzero probe exit prints a distinct startup `NOTICE` naming the exit code (`runsc failed to start or complete probe containers (exit N)`), with identical healing and fail-closed behavior. `--shell` runs never auto-select (explicit `--docker-fallback` there); `--runsc` forces gVisor with no probe.
